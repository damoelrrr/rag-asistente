Consulta usada para buscar: Hola soy Daniel, en un sistema RAG ¿Qué pasa en la etapa de indexing? Quiero entender cómo se dividen los documentos en chunks y para qué sirven los embeddings y la base de datos vectorial cuando el usuario hace una pregunta
Transcripción → respuesta (6.6 s):
En la etapa de **indexing** se prepara el material para que el modelo pueda buscarlo rápidamente cuando llegue una consulta. Primero se **limpia y extrae** los datos de los documentos (PDF, HTML, Word, Markdown, etc.) y se convierten a texto plano uniforme[2†L1-L4]. Luego ese texto se **segmenta** en fragmentos más pequeños llamados *chunks*; la estrategia más habitual es dividir por un número fijo de tokens (por ejemplo 100, 256 o 512)[1†L1-L4].  

Cada chunk se **codifica** con un modelo de embeddings, generando una representación vectorial que captura su significado semántico[2†L5-L8]. Esos vectores se **almacenan** en una base de datos vectorial. Cuando el usuario formula una pregunta, el mismo modelo de embeddings transforma la consulta en un vector y la base de datos realiza una búsqueda de similitud para encontrar los *k* chunks más relevantes[2†L9-L12][3†L2-L4]. Así, los chunks y sus embeddings permiten que el sistema recupere rápidamente la información contextual adecuada antes de que el LLM genere la respuesta final.

Consulta usada para buscar: Soy Daniel, según la ingeniería de Prompt, ¿cuáles son los componentes de un prompt correcto? Por ejemplo, ¿qué diferencia hay entre la tarea, el formato y el contexto y para qué sirven las restricciones?
Transcripción → respuesta (23.0 s):
Los componentes básicos de un prompt correcto son:

* **Task (Tarea)**: indica la acción concreta que debe ejecutar la IA, por ejemplo “explica cómo funciona el protocolo HTTP”. Es el objetivo principal del prompt[1†L1-L2].  
* **Context (Contexto)**: aporta información de fondo que ayuda al modelo a adaptar su respuesta al público o la situación, como “tu audiencia son niños de 8 años”. Sirve para que la salida sea relevante y adecuada al entorno[1†L1-L2].  
* **Format (Formato)**: define la forma en que debe presentarse la respuesta (lista, tabla, párrafo, código, etc.). Así el modelo sabe cómo estructurar la salida.  
* **Tone (Tono)**: establece el estilo o registro del texto (formal, informal, técnico, amigable).  
* **Constraints (Restricciones)**: son reglas que la respuesta debe cumplir o evitar, por ejemplo “no uses tecnicismos innecesarios” o “incluye al menos tres referencias”. Limita y guía la generación para que cumpla requisitos específicos[4†L9-L13].

En resumen, la **tarea** dice *qué* hacer, el **formato** indica *cómo* presentar la respuesta, el **contexto** explica *para quién* y *en qué situación* se da, y las **restricciones** establecen *qué* se debe o no incluir.
